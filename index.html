01 · building blocks

Five components cover most pages

Each component is a reusable website object with parameters, not a pixel picture. Change a parameter — the page changes. No markup edits.

Hero

Full-bleed opening block: headline, lead, call to action and a background layer.

Button

Variants, sizes and states as parameters. Keyboard- and screen-reader-friendly by default.

Card

Bordered surface with title, body and optional icon slot. The workhorse of any layout.

Gallery

Responsive image grid with lazy loading and a caption line per item.

Navigation

Sticky bar with brand slot, links and a burger fallback on narrow screens.

Parameters, not pictures

A component instance is data: {"type":"Button","label":"Go","size":"lg"}. The runtime renders it; the exporter prints it as static markup.

03 · export

The export owns nothing

An exported site is four plain things. Open it from a USB stick in 2035 — it still works.

exported-site/
├── index.html
├── style.css
├── script.js
└── assets/
  • No runtime licence check, no beacon, no CDN requirement.
  • CSS is printed from the same tokens the editor previews.
  • JavaScript is emitted only if the project actually animates.
  • Assets are copied, hashed and referenced relatively.
04 · project format

A project is one readable file

Pages, components, parameters, assets, animations and settings — plain data, diffable in git.

{
  "pages":     [ "home", "about" ],
  "components":[ { "type": "Hero", "title": "Hello", "cta": "Start" } ],
  "parameters":{ "radius": 14, "gap": 24 },
  "assets":    [ "logo.png" ],
  "animations":[ { "target": "hero", "channel": "opacity", "from": 0, "to": 1, "ease": "out" } ],
  "settings":  { "theme": "dark", "lang": "en" }
}
